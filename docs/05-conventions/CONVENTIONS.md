# 코드 규칙

> **코드를 어떻게 짜는가.**

## 1. 파일 위치

| 경로             | 담는 것                               | 의존                     |
| ---------------- | ------------------------------------- | ------------------------ |
| `src/routes/`    | 라우트 선언. TanStack Router          | `router.tsx`             |
| `src/router.tsx` | 라우터 생성. `getRouter`를 내보냄     | `routes/`                |
| `src/app/`       | 앱 뼈대. 전역 스타일                  | —                        |
| `src/lib/`       | 제품 계산. 순수 함수                  | **기획이 끝난 뒤 생성**  |
| `src/data/`      | 시드 + 수집 스냅샷                    | 리프                     |
| `src/ui/`        | 화면 컴포넌트. React                  | `lib/` + `data/`         |
| `src/pages/`     | 화면 단위. 라우트가 가리키는 곳       | `lib/` + `data/` + `ui/` |
| `scripts/`       | CLI 진입점. **호스트 환경 참조 가능** | `src/`                   |
| `test/`          | `node --test`. 한 파일 = 한 모듈      | 전부                     |

`src/lib/`, `src/data/`, `src/ui/`, `src/pages/`는 **기획이 끝난 뒤** 만듭니다. 요청
없이 빈 폴더를 만들지 않습니다.

**판단은 `lib/`에 있고 컴포넌트는 그리기만 합니다.** 컴포넌트가 조건을 새로 만들면
판단이 둘로 갈라져 표시가 서로 모순됩니다.

## 2. 명명

| 종류                         | 규칙                 | 예                                    |
| ---------------------------- | -------------------- | ------------------------------------- |
| 파일 · 디렉터리              | `kebab-case`         | `units.ts`, `use-form.ts`, `types.ts` |
| 컴포넌트 · 타입 · 인터페이스 | `PascalCase`         | `ResultCard`, `SystemInput`           |
| 변수 · 함수 · 훅             | `camelCase`          | `isLoading`, `estimateCost`           |
| 상수                         | `UPPER_SNAKE_CASE`   | `MAX_INPUT`, `DEFAULT_UNIT`           |
| 이벤트 핸들러                | `handle*` 접두사     | `handleClick`, `handleKeyDown`        |
| 열거 값                      | 소문자 문자열 유니온 | `'low' \| 'medium' \| 'high'`         |

함수 서명은 **동사 + 목적어** (`analyze*` / `estimate*` / `compute*` / `is*` /
`find*` / `resolve*`). `get*`는 게터가 필요하지 않습니다 — 필드 접근으로 충분합니다.

**파라미터 5개를 넘으면 질문 두 개가 섞여 있는 것입니다.** 나누십시오.

## 3. 선언과 export

- 모든 선언은 **`const` 화살표 함수**로 통일합니다
- **`named export`**가 기본입니다. `default export`는 지양합니다 (프레임워크 라우팅
  규약 파일 제외)
- **조기 리턴**으로 들여쓰기 깊이를 최소화합니다

### 파일 내부 배치 순서

**컴포넌트 파일 (`.tsx`)**: import → 파일 전용 상수 → 메인 선언 → 파일 내부 전용 보조
컴포넌트 (외부 export 없음)

**로직 파일 (`.ts`)**: import → 로컬 상수 · 초기 상태 → 메인 함수 → 내부 전용 보조 함수

⚠️ `const`는 호이스팅되지 않습니다. `createFileRoute('/')({ component: Home })`가
`const Home`보다 위에 있으면 `Block-scoped variable 'Home' used before its
declaration`로 빌드가 죽습니다. 보조 컴포넌트를 먼저 선언합니다.

## 4. 타입

- 타입은 컴포넌트 파일에 인라인으로 두지 않고 **`types.ts`로 분리**합니다
- 객체 모델은 `type`보다 **`interface`를 우선**합니다
- **`any` 금지.** `unknown`은 허용하지만 즉시 좁혀야 합니다
- `enum` 대신 `as const` 객체 맵 또는 문자열 유니온

### 실패 표현

```ts
// ✗ 조용히 기본값
const value = BY_KEY[key] ?? DEFAULT_VALUE;

// ✓ 추측하지 않습니다
const value = BY_KEY.get(key);
if (!value) return null;
```

실패 가능한 반환은 `T | null`이고, **호출부가 판단**합니다. 이 규칙을 어기면 틀린 값이
조용히 통과합니다.

## 5. 주석

파일 맨 위에 블록 주석을 둡니다. **왜 이렇게 됐는지**를 적습니다.

**넣습니다:** 무엇인지 · 왜 그런지 · 전제가 깨지면 · 하지 않는 것 · 예전에 밟은 함정

**넣지 않습니다:** 코드만 봐도 아는 것 (`// i를 1 증가`) · TODO (이슈로 옮깁니다)

## 6. 한국어

식별자는 영어, 설명·문서·주석·사용자에게 보이는 문자열은 한국어입니다.

**세 가지를 씁니다:**

1. **무엇인지** — 약어·필드명을 풀어 씁니다
2. **왜 그런지** — 괄호에 원인을 숨기지 않습니다
3. **안 하면 뭐가 깨지는지** — 경고를 분명히 씁니다

**어미는 합쇼체(합니다·입니다)로 씁니다.** 한 문서 안에서 합쇼체와 한다체가 섞이면
어느 쪽이 정본인지 읽는 사람이 판단해야 합니다.

| ✗                                        | ✓                                                              |
| ---------------------------------------- | -------------------------------------------------------------- |
| `isFaster: boolean`                      | `A 가 B 보다 빠른가`                                           |
| `늦어 보입니다 (원인 A + 원인 B가 직렬)` | `늦어 보입니다. 원인 A와 원인 B가 직렬로 이어지기 때문입니다.` |
| `그냥 넘어간다`                          | `조용히 넘어가면 안 됩니다. 틀린 값이 데이터에 남습니다.`      |

**직역하지 않습니다.** 영어 관용구를 글자만 붙여 붙이지 않습니다. 읽고 나서 무엇이
어떻게 바뀌는지 그릴 수 있으면 통과입니다.

**인용문은 존대로 바꾸지 않습니다.** 인용까지 고치면 대비가 사라집니다.

## 7. 스타일링

- **Tailwind 우선.** 조건부 클래스는 `cn`(`clsx` + `tailwind-merge`)
- 런타임 계산값은 CSS 변수 주입 + `h-[var(--custom-val)]`로 제어합니다
- **A11y**: 대화형 요소에 시맨틱 태그, `aria-label`, 키보드 접근

## 8. 포맷

`.editorconfig`와 `prettier.config.mjs`가 고정합니다: 작은따옴표, 세미콜론, 2칸
들여쓰기, 후행 쉼표, LF. 편집기마다 결과가 다르면 리뷰가 불가능해집니다.

## 9. 테스트

- **순수 로직·비즈니스 계산은 필수.** 기준값을 **하드코딩**합니다. 재계산해서 비교하면
  자기 자신을 검증하는 것입니다
- **실패한 형태를 고정합니다.** 성공 경로만 테스트하면 회귀를 못 잡습니다. 실제로
  실패했던 입력을 그대로 넣습니다
- **검증 환경은 중립입니다.** 개발 장비의 실측값과 대조하지 않습니다. 레퍼런스 스펙을
  픽스처로 주입합니다
- **N회 반복해 편차를 봅니다.** 1회 실측은 값이 아닙니다. 재현되지 않으면 박지 않습니다

### 두 러너

| 명령               | 보는 파일           | 하는 일                                   |
| ------------------ | ------------------- | ----------------------------------------- |
| `pnpm test`        | `test/**/*.test.ts` | 판단·순수 로직 (`node --test`)            |
| `pnpm run test:ui` | `src/**/*.test.tsx` | 화면 (Vitest + RTL) — 화면이 생긴 뒤 도입 |

`pnpm test`만 돌리고 "전부 통과"라고 보고하면 **화면 테스트를 안 돌린 것**입니다.

## 10. 구조 규칙은 테스트가 지킵니다

문서에 적힌 규칙은 깨집니다. 테스트에 적힌 규칙은 유지됩니다. 새 구조 규칙을 정하면
문서만 고치지 말고 테스트도 추가합니다.

⚠️ **같은 규칙을 ESLint에 두 벌로 두지 않습니다.** 구조를 강제하는 검사와 코드가
읽히는지를 보는 린트는 답하는 질문이 다릅니다. 한 규칙이 두 곳에 있으면 어느 쪽이
진짜인지 알 수 없고, 둘 다 통과해도 구조는 어긋나 있습니다.
