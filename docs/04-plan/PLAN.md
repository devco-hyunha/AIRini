# 실행 계획

> **언제 · 무엇을 · 왜 그렇게.** Phase 정의 · 이슈 · ADR.

## Phase 정의

**참조하기 전에 정의합니다.** 게이트가 기준 개념을 정의하지 못한 채 참조만 하면
게이트가 조용히 느슨해집니다. Phase를 참조하는 문서는 이 표를 가리킵니다.

| Phase           | 산출물                                                         | 승인 조건                              | 승인 주체 | 상태     |
| --------------- | -------------------------------------------------------------- | -------------------------------------- | --------- | -------- |
| **0 기준선**    | 도구 설정, `AGENTS.md`, `docs/`, CSR 셸, 첫 테스트, 첫 커밋    | `pnpm run verify` 경고 0 + 커밋 존재   | 사용자    | **완료** |
| **1 기획 확정** | `00-product/`, `01-requirements/`, 이 문서의 Phase 표가 채워짐 | 각 AC가 판정 가능한 형태("~이면 통과") | 사용자    | 미시작   |
| **2 첫 화면**   | 사용자 입력 → 선택 → 결과 표시, 근거 표시 포함                 | 브라우저에서 눈으로 확인               | 사용자    | 미시작   |
| **3 계산 엔진** | 순수 계산 + 실측 기준값 테스트                                 | 기준값 하드코딩 + 출처 주석            | 사용자    | 미시작   |

### Phase 0의 승인 조건

- `pnpm run verify`가 typecheck · lint · test · format:check 전부 통과
- `dist/client/index.html`이 `<!DOCTYPE html>`으로 시작하는 HTML 문서
- Git 커밋이 존재 (`git log`가 빈 이력으로 남지 않음)

## 이슈

코드 주석에 TODO를 남기지 않습니다. 지금 못 하는 것은 여기에 남깁니다.

| 번호 | 내용                                                               | 상태                 |
| ---- | ------------------------------------------------------------------ | -------------------- |
| I1   | 제품이 무엇인가 — `00-product/` 채우기                             | **미정의 (Phase 1)** |
| I2   | 화면 테스트 러너(Vitest) 도입 — 화면이 생긴 뒤                     | 미시작               |
| I3   | `pnpm test`가 빌드를 돌린다. 게이트가 느려지는 자리 — 실측 후 판단 | 진행                 |
| I4   | Node 버전 고정 실측 — `engine-strict`가 실제로 막는지 확인         | 미확인               |
| I5   | React Compiler (`viteReact({ compiler: true })`) 미도입            | 미시작               |

> **I5의 이유**: `compiler: true`는 `oxc-transform-react`를 peer로 요구합니다. 의존성을
> 하나 더 늘리는 결정이고, 메모화 이득이 이 저장소에서 실측되지 않았습니다. 실측 없이
> 의존성을 넣으면 그 의존성이 제품인지 하네스인지 알 수 없습니다.

## ADR

새 함정을 발견하면 여기에 남깁니다.

| 번호 | 결정                                                   | 이유                                                                                                                                                                           |
| ---- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D-1  | CSR(SPA 모드) + `prerender.outputPath = '/index.html'` | 기본값 `/_shell.html`은 `/* /_shell.html 200` 리다이렉트를 요구합니다. 정적 호스팅은 `index.html`을 기본 문서로 내줍니다                                                       |
| D-2  | 루트 라우트는 `component`로 문서를 만듭니다            | `shellComponent`는 클라이언트 렌더 경로에서만 적용됩니다. 서버 프리렌더는 `MatchView`로 빠집니다. `shellComponent` 단독 빌드는 셸이 HTML 문서가 아니었습니다 (2026-10-01 실측) |
| D-3  | `verbatimModuleSyntax`를 켜지 않습니다                 | 켜면 서버 번들이 클라이언트 번들에 새어 들어갑니다 (공식 문서 권고)                                                                                                            |
| D-4  | `.cursor/rules`를 만들지 않습니다                      | `AGENTS.md`가 같은 내용을 담으면 중복이고, 복사한 쪽이 먼저 낡습니다                                                                                                           |
| D-5  | Vitest는 화면이 생긴 뒤 도입합니다                     | 하네스가 제품보다 먼저 커지는 것을 막습니다                                                                                                                                    |
