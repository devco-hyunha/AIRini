# 문서 지도

코드를 바꾸기 전에 이 표로 문서 위치를 정합니다. 한 내용을 두 문서에 적지 않습니다.
복사한 쪽이 먼저 낡습니다.

| 내용                                  | 문서                                                  | 답하는 질문               |
| ------------------------------------- | ----------------------------------------------------- | ------------------------- |
| 왜 이 제품이 있는지, 무엇을 안 하는지 | [`00-product/`](00-product/PRODUCT.md)                | 왜 · 무엇을               |
| "~이면 통과" (AC)                     | [`01-requirements/`](01-requirements/REQUIREMENTS.md) | 무엇을 만들었나           |
| 수식, 타입, 모듈 경계                 | [`02-design/`](02-design/DESIGN.md)                   | 어떻게 계산하는가         |
| 데이터 출처·신뢰도·신선도             | [`03-data/`](03-data/DATA.md)                         | 데이터가 어디서 왔나      |
| Phase 정의·이슈·ADR                   | [`04-plan/`](04-plan/PLAN.md)                         | 언제 · 무엇을 · 왜 그렇게 |
| 코드를 짜는 규칙                      | [`05-conventions/`](05-conventions/CONVENTIONS.md)    | 코드를 어떻게 짜는가      |

## 문서 규칙

### 요건 문서에 근거를 적지 않습니다

`01-requirements/`에는 **판정이 아니라 판정만** 적습니다. "왜 이렇게 하는가"는
`00-product/`의 몫입니다. 두 곳에 같은 판단이 있으면 어느 쪽이 진짜인지 알 수 없습니다.

### 검증하지 않은 가정을 적지 않습니다

가설은 **한 번이라도 확인한 뒤**에만 적습니다. "~일 것이다"를 문서·주석에 남기지
않습니다. 확인 전에 결론을 적으면 그다음 작업이 틀린 전제 위에서 이어집니다.

### 이슈는 `04-plan/`에 남깁니다

코드 주석에 TODO를 남기지 않습니다. 지금 할 수 있으면 하고, 못 하면 이슈로 옮깁니다.

### 결정은 ADR로 남깁니다

새 함정을 발견하면 `04-plan/`의 ADR에 추가합니다. 함정은 "왜 이렇게 됐는지"의 원본이고,
코드에서 사라진 이유를 되찾는 자리입니다.

### 개수·수치를 적지 않습니다

모듈 개수·테스트 개수·줄 수를 문서에 적지 않습니다. 파일이 추가될 때마다 거짓이 됩니다.
**세고, 기준점은 경로로만 적습니다.**
