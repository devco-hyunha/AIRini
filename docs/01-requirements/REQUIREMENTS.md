# 요건

> **무엇을 만들었나 (AC로 판정).** "왜 이렇게 하는가"는
> [`00-product/`](../00-product/PRODUCT.md)의 몫입니다. 이 문서에 근거를 적지
> 않습니다.

## AC 형식

```text
FR-N: <만든 것>
  AC: <조건> → <보이는 결과>
  상태: 미정의 / 진행 / 완료
```

"~이면 통과"의 형태만 적습니다. 판정할 수 없는 문장은 AC가 아닙니다.

## 현재 상태

**미정의.** Phase 1에서 정의합니다.

| 번호 | 요건                                         | AC                                          | 상태 |
| ---- | -------------------------------------------- | ------------------------------------------- | ---- |
| FR-0 | 기준선: CSR 셸이 진짜 HTML 문서로 빌드됩니다 | `pnpm test`가 셸 본문을 검사하고 통과합니다 | 완료 |

> FR-0은 제품 요건이 아니라 **도구 전제**입니다. 2026-10-01에 `build`가 성공하고
> 프리렌더가 1페이지를 만들었는데 산출물이 HTML 문서가 아닌 상태가 있었습니다. 성공
> 여부만 보면 오판합니다. 본문을 봐야 알 수 있습니다.

## 요건을 바꿀 때

요건을 바꾸면 이 문서를 먼저 고칩니다. 코드가 먼저 가면 문서가 사실을 따라가지
못합니다.
